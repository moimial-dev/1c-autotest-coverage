# АвтоТест1С — автотесты и покрытие «из коробки»

Внешняя обработка (`.epf`) для автоматического тестирования конфигураций 1С.
Работает на любой конфигурации без предварительной настройки: подключились к базе,
нажали «Выполнить прогон» — получили результат. Писать сценарии не нужно.

## Что делает

**1. Автопрогон «из коробки».** Строит карту объектов конфигурации и сама проверяет
каждый: открытие форм, создание объектов, проведение документов, права, персональные
данные, изоляцию контура.

**2. Генератор UI-сценариев для [Vanessa Automation](https://github.com/Pr-Mex/vanessa-automation).**
Собирает `.feature`-файлы по карте объектов: списки, формы создания, отчёты, команды
разделов, печатные формы, ввод на основании. Набор обновляется вместе с конфигурацией
и не требует ручной поддержки.

**3. Отчётность.** Карта объектов, покрытие, риск-карта, покрытие интерфейса.
Выгрузка в JSON (для CI), HTML (для чтения) и MXL (для печати).

## Быстрый старт

1. Открыть `build/АвтоТест1С.epf` в режиме «1С:Предприятие» (Файл → Открыть).
2. Нажать **«Выполнить прогон»**.
3. Нажать **«Сохранить отчёты»**.

Все пути по умолчанию ведут в `C:\1C-auto\АвтоТест1С`; каталога может не быть —
обработка создаёт его сама.

Набор сценариев для Vanessa: заполнить группу «Сценарии Vanessa Automation»
и нажать **«Сгенерировать сценарии Vanessa»**.

## Чем полезна

* **Набор собирается под конкретного пользователя** — только доступные ему по правам
  объекты и видимые в его меню разделы; сценарии выполняются под ним же.
* **Учитываются функциональные опции** — объекты, скрытые выключенной опцией,
  в набор не попадают, и проверки не падают на том, чего в интерфейсе нет.
* **Исключения объектов файлами** — формат совпадает с генератором дымовых тестов
  xddTestRunner: строка `ИмяОбъекта[.ТипПроверки]`, поддерживаются маски.
* **Разбор результатов прогона** — штатные отказы конфигурации («только на основании»,
  «не выбран сегмент») уходят в исключения автоматически, остальные падения остаются
  человеку. Настоящие дефекты исключениями не прячутся никогда.
* **Критичность объектов 1–3** — быстрый набор на каждый коммит, полный на ночь.
* **Читающие и пишущие наборы** разделены тегом `@ИзменяетДанные`.
* **Раскладка по потокам** для параллельного прогона.
* **Пакетный режим для CI/CD** — прогон и выгрузка отчётов без участия человека.

## Как устроены сценарии

Сценарии ждут событий, а не отсчитывают паузы: открытия формы по имени, появления
нового окна, заполнения табличного документа. Таймаут — верхняя граница на худший
случай, а не время простоя.

```gherkin
Дано Я открываю навигационную ссылку "e1cib/list/Документ.ПоступлениеТоваров"
И я жду открытия формы с именем "Документ.ПоступлениеТоваров.Форма.ФормаСписка" в течение 8 секунд
Тогда открылась форма с именем 'Документ.ПоступлениеТоваров.Форма.ФормаСписка'
И я закрываю все окна клиентского приложения
```

Печать проверяется по-настоящему: команда печати берётся у БСП (а не угадывается
по макетам), документ ищется запросом при прогоне — проведённый и непомеченный, —
а проверяется не факт открытия окна, а заполнение печатной формы данными. Пустая
печатная форма и есть тот дефект, ради которого пишется тест.

```gherkin
И я выполняю код встроенного языка на сервере с передачей переменных
"""bsl
	Запрос = Новый Запрос("ВЫБРАТЬ ПЕРВЫЕ 1 Т.Ссылка КАК Ссылка ИЗ Документ.ОприходованиеТоваров КАК Т
		ГДЕ Т.Проведен И НЕ Т.ПометкаУдаления УПОРЯДОЧИТЬ ПО Т.Дата УБЫВ");
	Выборка = Запрос.Выполнить().Выбрать();
	Если Выборка.Следующий() Тогда
		Контекст.Вставить("ЕстьЧтоПечатать", "Да");
		Контекст.Вставить("СсылкаНаОбъект", ПолучитьНавигационнуюСсылку(Выборка.Ссылка));
	Иначе
		Контекст.Вставить("ЕстьЧтоПечатать", "Нет");
	КонецЕсли;
"""
Если переменная "ЕстьЧтоПечатать" имеет значение "Да" Тогда
	Дано Я открываю навигационную ссылку "$СсылкаНаОбъект$"
	И я жду открытия формы с именем "Документ.ОприходованиеТоваров.Форма.ФормаДокумента" в течение 8 секунд
	И я нажимаю на кнопку с именем 'ПодменюПечать*__АктОбОприходованииТоваров'
	И я жду открытия формы с именем "ОбщаяФорма.ПечатьДокументов" в течение 30 секунд
	И я жду, что табличный документ "ПечатнаяФорма1" заполнится данными в течение 30 секунд
```

## Пакетный режим для CI/CD

```
1cv8 ENTERPRISE /F<база> /Execute АвтоТест1С.epf /CАвтоТест1С;<каталог отчётов>;<лимит объектов>;<лимит форм>
```

Лимиты необязательны: `0` — без ограничения, `-1` для форм — не обходить интерфейс.
По завершении отчёты сохраняются в указанный каталог, сеанс закрывается.

## Сборка из исходников

```
1cv8.exe DESIGNER /F<пустая база> /LoadExternalDataProcessorOrReportFromFiles "src\АвтоТест1С.xml" "build\АвтоТест1С.epf"
```

## Требования

* Платформа 1С:Предприятие 8.3 (проверено на 8.3.27).
* Vanessa Automation для прогона сценариев (проверено на 1.2.043).
* Библиотека стандартных подсистем (БСП) — для проверки печатных форм.
* Права: полный прогон — администратор; генерация набора под пользователя —
  достаточно чтения метаданных.

Проверено на «1С:Розница» 2.3.

## Ограничения

* **Видимость команд панели функций** из метаданных не читается — лечится исключениями
  вида `Объект.КомандныйИнтерфейс` или выключенным флажком «Команды разделов».
* **Выбор печатной формы — эвристика**: предпочитается команда с признаком «основная
  печатная форма», но если конфигурация их не проставляет, берётся первая по списку.
* **Команды печати с диалогом параметров** сценарий не проходит — такие объекты
  вносятся в исключения.
* **Данные с управляющими символами** (коды маркировки с разделителем GS) не передаются
  между клиентом и сервером в XML: Vanessa падает модальным окном и вешает прогон,
  поэтому такие объекты исключают заранее.
* **Набор привязан к базе** — к её правам, функциональным опциям и составу данных;
  при смене базы набор перегенерируют.
